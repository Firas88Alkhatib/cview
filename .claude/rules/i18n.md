# i18n rules (@nuxtjs/i18n, D-20)

- No hard-coded user-facing text in templates or scripts. Use `$t('key')` in templates and `const { t } = useI18n()` in scripts.
- Add every new key to `i18n/locales/en.json`, nested by area: `common.*`, `topbar.*`, `editor.<section>.*`,
  `preview.*`, `versions.*`, `validation.*`.
- Zod schemas stay language-agnostic. Error messages are **keys** (e.g. `'validation.required'`) that the
  form layer translates. Don't call `t()` inside schemas. Verify how `UForm` surfaces messages and translate them at display time.
- Use interpolation and pluralisation (`t('versions.count', { n })`), never string concatenation.
- Format dates and numbers through i18n/`Intl`, never manually.
- PDF text is **not** UI i18n (D-23). It comes from `app/pdf/locales/<pdfLocale>.ts`. Never use `useI18n`
  inside `app/pdf/**`.
- Tests: query by the English text, or use the key value from `en.json`. Don't hard-code duplicated strings in many tests.
